# Publishing FollowExam on Google Play

FollowExam ships as a **Trusted Web Activity (TWA)**. The Android app opens the live
site at `https://followupdates.web.app` in a full-screen Chrome-backed window, so a
web deploy updates the app instantly without shipping a new APK.

Everything that can be prepared without a paid account is already in the repository:

| Item | Status |
| --- | --- |
| Web app manifest | `public/manifest.webmanifest` |
| PNG icons (192, 512, maskable) | `public/icons/` (generated by `npm run icons:build`) |
| Service worker | `public/sw.js` (registered in production only) |
| Offline fallback | Inline page inside `public/sw.js` |
| TWA configuration | `twa-manifest.json` |
| Package id | `app.web.followupdates.twa` |
| Version code | `1` (`appVersionCode` in `twa-manifest.json`) |

## 1. What you need

1. A **Google Play Console** developer account — one-time **US$25** fee.
2. **Node.js 20+** and **JDK 17** on the build machine.
3. **Android SDK** build tools. Bubblewrap can download them on first run.
4. A **keystore** for signing. Keep it and its passwords safe; losing it blocks updates.
5. An **email address** for the store listing and a **public privacy policy URL**
   (`https://followupdates.web.app/privacy/` already exists).

Bubblewrap creates the Android project from `twa-manifest.json`; do not hand-edit the
generated `app/` folder unless you need a native feature.

## 2. Create the signing key

```bash
keytool -genkeypair -v \
  -keystore android.keystore \
  -alias followexam \
  -keyalg RSA -keysize 2048 -validity 10000
```

`android.keystore` is git-ignored. Back it up offline (password manager + encrypted
drive). Never commit it.

## 3. Build the app

```bash
npm install -g @bubblewrap/cli
bubblewrap init --manifest https://followupdates.web.app/manifest.webmanifest
```

Answer the prompts using `twa-manifest.json` as the reference. Then:

```bash
bubblewrap build
```

Outputs:

- `app-release-signed.apk` — install on a test phone.
- `app-release-bundle.aab` — upload this to Play Console.

Test the APK on a real device before uploading:

```bash
adb install -r app-release-signed.apk
```

If the address bar is visible, Digital Asset Links are not verified yet (step 4).

## 4. Verify the domain (Digital Asset Links)

Without this step the app opens with a browser address bar instead of full screen.

1. Upload the first build to Play Console (internal testing is enough).
2. Open **Release → Setup → App signing** and copy the **SHA-256 certificate
   fingerprint** of the *app signing key* (not the upload key).
3. Create `public/.well-known/assetlinks.json`:

```json
[
  {
    "relation": ["delegate_permission/common.handle_all_urls"],
    "target": {
      "namespace": "android_app",
      "package_name": "app.web.followupdates.twa",
      "sha256_cert_fingerprints": [
        "AA:BB:CC:...:REPLACE_WITH_PLAY_SIGNING_SHA256"
      ]
    }
  }
]
```

4. Deploy hosting: `firebase deploy --only hosting --project followupdates`.
5. Confirm the file is public:
   `https://followupdates.web.app/.well-known/assetlinks.json`.
6. Verify with Google:
   `https://developers.google.com/digital-asset-links/tools/generator`.

Re-check this file whenever Play rotates the app signing key.

## 5. Play Console listing

Use these values in **Grow → Store presence → Main store listing**:

- **App name:** FollowExam — Govt Exams & Scholarships (30 characters max)
- **Short description:** Official government job, exam and scholarship notifications with source links.
- **Full description:** describe the account-based feed, analysed notifications,
  exam cycles, institutions, scholarships and the career planner. Mention that every
  post links to the official notification.
- **App category:** Education
- **Tags:** Education, Government, Productivity
- **Contact email:** the address configured in `src/lib/constants.ts` (`SITE.email`)
- **Privacy policy:** `https://followupdates.web.app/privacy/`
- **Ads:** No
- **In-app purchases:** No

Graphics:

- **App icon:** `public/icons/icon-512.png` (512 × 512 PNG)
- **Feature graphic:** 1024 × 500 PNG/JPG (create from the icon and brand colours)
- **Phone screenshots:** 2–8 images, minimum 1080 px on the short side. Capture the
  login screen, dashboard, a job detail page, scholarships, institutions and the
  career planner.
- **Tablet screenshots:** optional but improves ranking on large screens.

## 6. App access (login required)

FollowExam shows content only after sign-in, so Play review needs credentials:

- **App access → All or some functionality is restricted → Add instructions.**
- Provide a test account email and password created in Firebase Authentication.
- Add the steps: open app → sign in with the test account → dashboard loads.

Keep the test account active until review finishes. If phone sign-in is enabled,
mention that Google or email sign-in is also available.

## 7. Data safety form

Declare what the app actually stores in Firestore and Firebase Authentication:

- **Collected:** name, email address, phone number (if phone sign-in is used),
  user IDs, and user-entered profile details (state, education level, stream,
  date of birth, career goal, interests).
- **Purpose:** account management, app functionality, personalisation.
- **Shared with third parties:** No (Firebase/Google acts as the data processor).
- **Encrypted in transit:** Yes.
- **Data deletion:** users can delete their profile from `/profile/`; also offer the
  contact email for deletion requests. Link the privacy policy.
- **Ads / analytics:** none beyond Firebase infrastructure.

## 8. Content rating and audience

- Complete the content rating questionnaire as a **reference/informational** app.
- Target audience: **13+**. The privacy policy states the service is not directed at
  children under 13.
- The app contains no user-generated public content, no gambling, no violence and no
  purchases, which keeps the rating straightforward.

## 9. Testing and release

New personal developer accounts must run **closed testing with at least 12 testers
for 14 continuous days** before production access is granted.

1. **Testing → Internal testing:** upload the `.aab`, add your own account, install
   from the opt-in link, and check sign-in, navigation and offline behaviour.
2. **Testing → Closed testing:** add 12+ testers (friends, classmates, a Telegram
   group), keep the release live for 14 days, and collect feedback.
3. **Production → Create release:** upload the same or a higher version code, complete
   the rollout checklist, and submit for review.

Review usually takes a few days. Respond quickly to any policy email.

## 10. Releasing updates

Web content updates do **not** need a new app release — the TWA loads the live site.
Build a new `.aab` only when you change:

- the app name, icon, theme colours or shortcuts (`twa-manifest.json`),
- the package id (never change it after the first upload),
- the minimum SDK or orientation.

Before each native release:

1. Increment `appVersionCode` (must always increase) and `appVersionName`.
2. Run `bubblewrap update` then `bubblewrap build`.
3. Upload the new `.aab` to the same track.

## 11. Current blockers

- The **US$25 Play Console fee** has not been paid, so the app cannot be uploaded yet.
- The **SHA-256 fingerprint** is only available after the first upload; until then the
  address bar stays visible in the TWA.
- **Phone sign-in** needs the Firebase **Blaze** plan for SMS quota. Google and email
  sign-in work on the free Spark plan, so the test account should use one of those.
- Keep `FIREBASE_SERVICE_ACCOUNT`, `SMTP_USER` / `SMTP_PASS` and the Telegram secrets
  configured in GitHub so the live site keeps updating while the app is in review.

## 13. Troubleshooting

| Symptom | Fix |
| --- | --- |
| Address bar visible | `assetlinks.json` missing, wrong package id, or wrong SHA-256. Redeploy and re-check. |
| White screen on launch | Start URL unreachable or offline. Check `startUrl` and hosting. |
| App opens in Custom Tab | Digital Asset Links not verified; the app falls back to `customtabs`. |
| Play rejects "login required" | Add working test credentials under **App access**. |
| Play rejects data safety | Match the form to the Firestore fields listed above. |
| Icon looks cropped | Use the maskable icon for the adaptive icon and keep the glyph inside the safe zone. |
